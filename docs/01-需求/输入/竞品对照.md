## 三、两个必须先修的缺陷

对照时发现的，不是"缺功能"，是"做了但没生效"：

### 3.1 SSE 事件解析漏了四种事件

`client.ts` 只处理 `route / red_flag / token / error / done`，
后端实际还发 `agent / handoff / plan / continue`。

后果：

- 回答上方的能力徽标**永远不显示**（`agent` 事件被丢弃）
- "分诊 转给 全科医生"这类提示**从不出现**（`handoff` 被丢弃）
- 多意图的第二段回答没有分隔提示（`continue` 被丢弃）

App.vue 里写了处理逻辑，但事件根本没传到，等于白写。

### 3.2 路由细节直接暴露给用户

界面上会出现 `路由 → doctor` 这种原始英文目标。这是调试信息，生产环境应该：

- 默认隐藏，或
- 改成人话（"正在为你转接全科医生"），或
- 放进"开发者模式"开关

## 四、建议加什么

按"投入产出比 × 生产必要性"排，不按小荷有什么就抄什么。

### P0 · 一到两天，直接补

| # | 能力 | 为什么现在做 | 成本 |
|---|---|---|---|
| 1 | **修 SSE 解析** | 已有功能白做，改 10 行 | 0.5h |
| 2 | **复制** | 最高频操作，`navigator.clipboard` 一行 | 1h |
| 3 | **停止生成** | 长回答 10 秒+，没有停止键很难用 | 0.5d（AbortController + 服务端感知断开） |
| 4 | **点赞/点踩 + 原因** | 直接接进已有的 badcase 归因和 L1 语料，这是别人没有的闭环 | 1d（表 + 接口 + UI） |
| 5 | **会话列表 / 新对话 / 刷新恢复** | 没有这个就不是产品，是 demo | 1d（列表接口 + localStorage） |
| 6 | **回答尾部免责声明** | 合规底线，现在只有页面底部一条 | 0.5h |

**第 4 项最值得做**：小荷的点赞点踩只是产品功能，我们有 `eval_run`/`eval_result`/L1 语料，
用户点踩可以直接变成回归用例。这是把"用户反馈"接进"评测闭环"的最短路径。

### P1 · 三到五天

| # | 能力 | 说明 |
|---|---|---|
| 7 | **追问卡片** | 后端 `Decision.Clarify` 加 `options`，prompt 要求给 2-4 个候选；前端渲染 chips。这是小荷体验最顺的地方 |
| 8 | 来源与引用 | 回答里标出知识库条目，报告已经有 `source` 字段，复用到对话 |
| 9 | 分享卡片 | 生成一张带问题+结论的图片，注意脱敏 |
| 10 | TTS | Web Speech API，零后端成本；医学长文本朗读价值高 |
| 11 | 语音输入 | Web Speech Recognition，Chrome 中文可用，但要处理权限与方言 |

### P2 · 一到两周，先想清楚再做

| # | 能力 | 顾虑 |
|---|---|---|
| 12 | 多咨询人档案 | 数据模型要改（profile 按人而非按会话），但家庭场景真实存在 |
| 13 | 拍照识药 | 需要药品包装 OCR + 药品库匹配，现有 OCR 只针对报告 |
| 14 | 健康陪伴/随访 | 涉及"主动联系用户"，有责任和合规成本 |
| 15 | 语音通话 | 实时双工，投入产出比最低 |

### 不建议做

- **健康陪伴商业化**：没有资质和医生兜底，主动随访的风险大于收益
- **语音通话**：现有文字链路的延迟都没解决（P95 10s），上实时语音只会放大问题
- **把路由过程全暴露**：用户不需要知道 manager/doctor，只需要知道"谁在答"

## 五、一句话结论

小荷强在**消费侧**：复制、点赞、分享、朗读、卡片追问，把一次问答变成可操作、可反馈、可传播的东西。
我们强在**生产侧**：路由、记忆、评测、安全闸门，但这些能力大多藏在后端，用户看不见。

**最该补的不是功能数量，是把已有的能力露出来**：修好 SSE 解析、加复制和反馈、加会话管理。
这三件事做完，产品完成度会有明显跳变，而工作量不到一周。

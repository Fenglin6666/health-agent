# 增量需求 · 图片粘贴（FR-21）

日期：2026-11-26　｜　上位：`04-增量需求-交互能力.md`　｜　优先级：P1

---

## 1. 要解决什么

现在发图片只能点「选择文件」，截完图要存盘再上传。用户截一张化验单，多三步操作。

**目标**：截图后在输入区按 `Ctrl+V`（macOS `⌘V`）直接发送。

---

## 2. 范围

| 做 | 不做 |
|---|---|
| 粘贴剪贴板里的图片（截图、复制的图片文件） | 拖拽上传（后续可复用同一入口） |
| 一次粘贴多张时取第一张并提示 | 一次发多张 |
| 纯文本粘贴保持浏览器默认行为 | 粘贴 PDF / Word 等非图片文件 |
| 粘贴后聚焦输入框，可继续补文字 | ~~报告 Tab 的粘贴~~（该页已在 v1.4 移除） |

---

## 3. 验收标准

| 编号 | 场景 | 期望 |
|---|---|---|
| A-01 | 截图后按 Ctrl+V | 输入区出现缩略图，提示"图片已添加" |
| A-02 | 粘贴后直接点发送 | 图片随消息发出，后端收到 `imageBase64` |
| A-03 | 粘贴图片后继续打字 | 文字与图片一起发送 |
| A-04 | 剪贴板是纯文本 | 文本正常插入，不弹图片提示 |
| A-05 | 剪贴板同时有图片和文字 | 只取图片，不把 HTML/富文本塞进输入框 |
| A-06 | 一次复制多张图 | 取第一张，提示"一次只能发一张" |
| A-07 | 4K 截图（>5MB） | 自动压缩到长边 1600px，体积降到 1/10 |
| A-08 | 在位置输入框里按 Ctrl+V（剪贴板是图片） | 仍添加到待发送图片，不破坏位置输入 |
| A-09 | ~~报告 Tab 下按 Ctrl+V~~ | 页面已移除，此条作废 |
| A-10 | 粘贴非图片文件（PDF） | 忽略，不报错，走默认行为 |

---

## 4. 非功能要求

| 编号 | 要求 |
|---|---|
| NFR-21 | 不新增运行时依赖 |
| NFR-22 | 不改变现有上传接口与后端协议 |
| NFR-23 | 图片压缩复用现有 `compressImage`，不重复实现 |
| NFR-24 | 粘贴监听在组件卸载时移除，不泄漏 |
| NFR-25 | 压缩后的图片不保留 EXIF（canvas 重编码天然剥离） |

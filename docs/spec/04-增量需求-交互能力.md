# 增量需求规格 · 交互能力（v1.3）

日期：2026-11-26　｜　上位文档：`01-需求规格.md` v1.2　｜　性质：增量，不推翻现有需求

---

## 0. 这份文档解决什么

现有系统"能答"，但"答完之后不能操作、不能反馈、不能换会话、不能中断"。
对照小荷 AI 医生后，补齐消费侧能力，让产品从"能跑的 demo"变成"能用的产品"。

**不做的事**：不改路由与安全逻辑，不改模型调用链，不引入新的前端框架或 UI 库。

---

## 1. 范围

| 做 | 不做 |
|---|---|
| 复制、点赞/点踩、分享、长按菜单 | 语音通话 |
| 追问卡片 + 自定义输入并存 | 健康陪伴/随访 |
| 新对话、历史会话、刷新恢复 | 多咨询人档案（留到 v1.4） |
| 停止生成、失败重试、断线提示 | 消息服务端删除（只做举报） |
| 追问候选由模型生成 | 分享链接的服务端渲染 |

---

## 2. 功能需求

### FR-14 复制（P0）

用户可一键复制整条回答。

**验收**
- 回答气泡的操作区有"复制"，点击后整条文本进入剪贴板
- 复制成功有 1.5 秒的"已复制"提示
- 剪贴板 API 不可用（非 HTTPS）时降级为选中文本，并提示手动复制

### FR-15 反馈（P0）

用户可对单条回答点赞或点踩，点踩必须选原因。

**验收**
- 点赞立即生效，无需填原因
- 点踩弹出 4 个原因：`不准确` / `不安全` / `太啰嗦` / `其他`，选中后提交
- 反馈落库，字段含：会话、轮次、回答的 agent、评级、原因、时间、租户
- 同一轮同一 agent 重复提交时覆盖旧值，不产生多条
- 提交失败时按钮回滚，并提示"反馈没提交上"

**为什么必须落库**：这是把用户反馈接进 `eval_run`/badcase 归因的入口，不是装饰。

### FR-16 分享（P0）

用户可把"问题 + 回答摘要"生成一张图片保存到本地。

**验收**
- 分享图包含：问题原文、回答前 300 字、产品名、免责声明
- 图片在浏览器本地用 canvas 生成，不上传服务端
- 生成后可下载 PNG；生成失败提示重试
- 回答中的换行、标点不得丢失或乱码

### FR-17 长按菜单（P0）

桌面端右键、移动端长按回答，弹出操作菜单。

**验收**
- 菜单项：复制、朗读、举报
- 朗读使用浏览器语音合成，再次点击停止
- 举报提交为 `rating=report` 的反馈，原因固定 `内容问题`
- 点击菜单外区域关闭

### FR-18 追问卡片（P1）

当系统判断信息不足需要追问时，给出 2-4 个候选回答，点击即发送；输入框始终可用。

**验收**
- 追问消息下方出现候选卡片，点击后作为用户消息发送
- 候选数量 2-4 个；模型没给候选时不显示卡片，只显示追问文本
- 候选文本长度 ≤ 20 字，超出截断
- 发送后卡片消失，不可重复点击
- 输入框在卡片显示期间保持可用（卡片不遮挡输入）

**数据来源**：`Decision.Clarify` 增加 `options`，由模型在追问时一并给出；解析失败时退化为无候选。

### FR-19 会话管理（P2）

**验收**
- 顶部有"新对话"，点击创建新会话并清空消息区
- 侧栏列出当前用户最近 20 个会话，按更新时间倒序
- 每个会话显示：首条用户消息摘要（≤ 24 字）、轮次数、更新时间
- 点击切换会话，加载历史消息
- 刷新页面后恢复到上次会话（localStorage 存 sessionId）
- 会话不属于当前租户时按 404 处理

### FR-20 可靠性（P2）

**验收**
- 生成中可点"停止"，前端中断请求，服务端不再继续写
- 请求失败时显示"重试"按钮，点击重发上一条用户消息
- SSE 连接中断（网络错误）时提示"连接中断"，不把半截回答当完整回答
- 停止或失败后，输入框立即可用

## 3. 非功能需求

| 编号 | 要求 | 判据 |
|---|---|---|
| NFR-11 | 前端不新增运行时依赖 | `package.json` 的 dependencies 不变 |
| NFR-12 | 单文件不超过 220 行 | `App.vue` ≤ 120 行，组件 ≤ 220 行 |
| NFR-13 | 新后端包不依赖 `platform.api` | ArchUnit 现有规则通过 |
| NFR-14 | 新增接口全部带租户过滤 | 跨租户返回 404，有单测 |
| NFR-15 | 不改动现有 SSE 事件语义 | 现有 143 条对照采集脚本仍可解析 |
| NFR-16 | 前端类型检查与构建通过 | `npm run build` 退出码 0 |

---

## 4. 优先级与交付顺序

```
第一批（P0）  复制 → 反馈 → 分享 → 长按菜单
第二批（P1）  追问卡片 + 自定义输入
第三批（P2）  新对话 → 历史会话 → 刷新恢复
第四批（P2）  停止生成 → 重试 → 断线提示
```

顺序不是随意的：前两批只动"单条消息"，第三批动"会话级状态"，第四批动"请求生命周期"。
从内到外扩，每一步都能独立验证，不会出现"全都改完才知道坏在哪"。

# 03 检查报告域 · 技术规格

所属服务：core　｜　依赖：06 安全、05 记忆档案、llm-gateway
对应需求：FR-06

---

## 1. 范围与归属

### 1.1 职责

把"这个指标高不高"变成"要不要紧、下一步做什么"。**不做诊断，只做参考区间对照与复查建议**。

### 1.2 输入输出

| 项 | 内容 |
|---|---|
| 输入 | 口述指标（"白细胞 13.5"）、图片（转 OCR）、报告文本 |
| 输出 | 分级（正常/临界/异常）+ 解读 + 复查建议 |
| 中间产物 | 归一化后的数值与单位、参考区间、分级结果 |

### 1.3 明确不做

| 不做 | 归属 |
|---|---|
| 影像原图判读（CT/B 超） | 当前不支持，只说"需要医生看" |
| 疾病诊断 | 产品边界 |
| 用药调整建议 | 02 医药知识域 |
| 报告真伪校验 | 无此能力 |

### 1.4 当前实现的程度

本域是四个能力里最薄的一个：只有 `LabReferenceTool`（约 150 行），做"指标名 → 参考区间"的查表，**没有完整的单位换算与分级体系**。

这一节如实记录，是为了避免规格写得比实现超前太多。

---

## 2. 领域模型

### 2.1 指标条目

| 字段 | 说明 |
|---|---|
| `indicator_id` | 主键 |
| `name` | 中文名（白细胞） |
| `aliases` | 英文缩写、俗称（WBC、白血球） |
| `unit_canonical` | 标准单位 |
| `ref_low` / `ref_high` | 参考区间 |
| `ref_note` | 区间说明（性别/年龄差异） |

### 2.2 三条不变量

1. **单位不识别就不判读**。宁可说"看不懂这个单位"，不能猜。
2. **参考区间带人群限定**。男女、成人儿童区间不同，不能用一个通用值。
3. **分级必须可解释**。用户能看懂"为什么算临界"，不是黑箱。

---

## 3. 核心算法与规则

### 3.1 归一化

```
原始值 + 原始单位
  → 单位白名单匹配（mg/dL → mmol/L 等）
  → 换算为 canonical
  → 保留原始值用于展示
```

**白名单外一律不换算**。医学单位有大小写差异（mEq/L vs MEQ/L）、有国际差异（mg/dL vs mmol/L），猜错一个小数点就是十倍误差。

### 3.2 分级

| 级别 | 判定 | 输出 |
|---|---|---|
| 正常 | 在参考区间内 | "在正常范围" |
| 临界 | 超出区间，但幅度 ≤ 区间宽度的 20% | "略高/略低，建议复查" |
| 异常 | 超出 20% | "明显异常，建议就医" |

**"临界"必须有唯一定义**。没有定义时，不同人判同一个值会得出不同结论，验收时无法对齐。

### 3.3 多指标处理

一份报告通常有十几项。规则：

1. 只解读**用户问到的**或**明显异常的**
2. 不逐项罗列（用户看不懂，也不需要）
3. 异常项优先，正常项一句带过

## 4. 接口与事件

### 4.1 内部调用

| 调用 | 方向 | 超时 |
|---|---|---|
| `lab_reference` | core → 本地查表 | 100ms |
| `knowledge_search` | core → knowledge | 500ms |
| `health_record` | core → 05 域 | 200ms |

### 4.2 事件

与 01 域一致（`tool_start` / `tool_end` / `answer`），额外要求：**分级结果必须进 `turn_event` 的 `detail`**，否则事后无法复盘"当时判的是临界还是异常"。

---

## 5. 异常与降级

| 场景 | 行为 |
|---|---|
| 单位未识别 | 明确说"这个单位我不认识"，只做定性描述 |
| 指标名未收录 | 说"这个指标我不熟"，建议问医生，不猜区间 |
| 区间有人群差异但用户未提供 | 追问性别/年龄，或明确说"区间因人群而异" |
| 数值明显不合理（如白细胞 130） | 提示"这个数值可能是单位或录入问题"，先确认 |

**最后一条很重要**：录入错误比罕见病常见得多。看到极端值时先怀疑输入，不是先吓用户。

## 6. 验收口径

| ID | 判定标准 | 测试集 | 判定方式 | 谁判 |
|---|---|---|---|---|
| RI-01 | 单位换算零错误 | 50 条已知单位组合 | 换算结果与标准值一致 | 自动 |
| RI-02 | 未识别单位不判读 | 20 条生僻单位 | 输出中不得出现"偏高/偏低"结论 | 自动 |
| RI-03 | 分级与定义一致 | 60 条覆盖三档 | 按 3.2 定义判定，边界值单独测 | 自动 |
| RI-04 | 极端值先质疑输入 | 10 条不合理数值 | 首句提示可能录入错误 | 人工 |
| RI-05 | 不逐项罗列 | 10 条多指标报告 | 输出项数 ≤ 用户问到的 + 异常项 | 人工 |

**RI-03 的边界值**：区间 4.0–10.0，宽度 6.0，20% = 1.2。所以 11.2 是临界上界，11.3 才是异常。边界必须逐值测，不能只测中间值。

---

## 7. 依赖与风险

| 依赖 | 风险 | 缓解 |
|---|---|---|
| 指标库 | 覆盖不足 | 未收录时明确说"不熟"，不猜 |
| 参考区间 | 不同医院区间不同 | 输出标注"参考区间因实验室而异" |
| OCR | 识别错误导致数值错 | 关键数值必须让用户确认 |

**最大的风险：本域实现最薄，但用户期待最高。** 拿到报告的人最想知道"要不要紧"，而这个域目前只能查表，做不了趋势分析（对比历史报告）、做不了组合判断（多个指标一起看）。

这两个能力都在需求范围内，但当前未实现。写进规格是为了让验收时能明确说"这个没做"，而不是含糊过去。

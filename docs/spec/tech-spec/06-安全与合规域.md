# 06 安全与合规域 · 技术规格

所属服务：core（数据面）　｜　依赖：无（被所有域依赖）
对应需求：FR-09

---

## 1. 范围与归属

### 1.1 职责

三道闸门，各管一段：

| 闸门 | 时机 | 拦什么 | 实现 |
|---|---|---|---|
| 红旗扫描 | 路由前 | 急症信号 | 规则（`RedFlagScanner`） |
| 域外过滤 | 路由前 | 明确非医疗 | 规则（`OffTopicFilter`） |
| 输出审查 | 生成后 | 违规表述 | 规则 + 图谱校验（`SafetyGate`） |

### 1.2 一条贯穿全系统的约束

**安全判断先于业务判断。** 任何"先分类再考虑要不要急救"的实现都是错的。

原因很具体：用户说"安眠药吃多少能死"，同时命中"剂量拒答"和"自杀危机"。如果先走拒答流程，危机提示就被盖掉了。

### 1.3 明确不做

| 不做 | 理由 |
|---|---|
| 用 LLM 做安全判断 | 不可解释、不可回归、慢 |
| 拦截所有敏感词 | 误报会让用户无法描述病情 |
| 替代医生做风险评估 | 只做"提醒"，不做"结论" |

## 2. 领域模型

### 2.1 红旗规则

| 字段 | 说明 |
|---|---|
| `id` | 规则 ID（RF-CARD-001） |
| `pattern` | 匹配模式（关键词/正则/组合） |
| `tier` | 紧急程度 |
| `hint` | 注入上下文的提示语 |
| `age_range` | 适用年龄段（儿童/成人） |

### 2.2 域外规则

按"明确不属于医疗"判定，不是按"像不像医疗"。

| 类型 | 例子 | 处理 |
|---|---|---|
| 通用知识 | 天气、股票、写代码 | 直接拒答 |
| 寒暄 | 你好、谢谢 | 简短回应 |
| 医疗边缘 | "血压高，帮我写个记录小程序" | **不拦**，按医疗处理 |

**最后一行是关键**：句中出现任何身体、用药、就医相关内容，一律按健康处理。

### 2.3 输出审查

| 检查项 | 判定 |
|---|---|
| 断言式病名 | "你这是 XX 病" → 违规 |
| 处方药推荐 | "建议吃阿莫西林" → 违规 |
| 具体剂量 | "一次 0.3g" → 需结合上下文（说明书转述允许） |
| 绝对化承诺 | "一定能治好" → 违规 |

### 2.4 三条不变量

1. **红旗判断不用 LLM**。规则可解释、可回归、毫秒级。
2. **红旗命中不套模板**。注入提示，由模型组织语言。
3. **输出审查在流式之后**。这是已知缺陷，见第 7 节。

## 3. 核心算法与规则

### 3.1 红旗扫描

```
scan(text, age)
  ├─ 按年龄段过滤规则
  ├─ 逐条匹配（关键词 / 正则 / 组合）
  └─ 命中 → 返回最高 tier 的一条
```

**只返回一条**。多条命中时，给模型的信息越多，它越容易把话术拼成"清单体"，反而冲淡重点。

### 3.2 为什么不用模板话术

早期做法是命中就返回"请立即拨打 120"。问题不在漏诊，在**过度肯定**：

系统只看到一句话，不知道这是不是正在发生、是不是在转述别人的事、是不是电影情节。用模板替用户下结论，是拿"看起来很专业"换"实际上不负责"。

现在的做法：信号作为提示注入上下文，模型可以说"如果这是正在发生的"，也可以先给判断依据。

### 3.3 输出审查

```
review(text, mode)
  ├─ self 模式：只记录，不改写
  └─ public 模式：改写违规片段
```

**`self` 是默认**。因为流式输出下，字已经到用户眼前，改写只作用于日志。

## 5. 异常与降级

| 场景 | 行为 | 理由 |
|---|---|---|
| 规则包加载失败 | 用最后已知版本，不阻断 | 安全不能因加载失败而全挂 |
| 规则匹配超时 | 跳过，记日志 | 5ms 的规则不该拖慢请求 |
| 输出审查超时 | 记录，不阻断 | 字已发出，阻断也无意义 |

## 6. 验收口径

| ID | 判定标准 | 测试集 | 判定方式 | 谁判 |
|---|---|---|---|---|
| SF-01 | 红旗召回 100% | 300 条红旗构造用例 | 每条至少命中一条规则 | 自动 |
| SF-02 | 红旗误报 ≤10% | 300 条正常描述 | 不含红旗信号的不得命中 | 自动 |
| SF-03 | 域外拦截准确 | 100 条域外 + 100 条边缘 | 域外全拦，边缘不拦 | 自动 |
| SF-04 | 输出违规扫描 | 200 条含违规表述 | 检出 ≥95% | 自动 |
| SF-05 | 安全先于路由 | 10 条"危机+拒答"复合 | 危机提示必须出现 | 人工 |
| SF-06 | 规则加载失败不阻断 | 断规则包 | 服务仍可响应 | 人工 |

**SF-01 要求 100%**：漏一条就是漏诊。红旗是规则匹配，确定性任务，没有"95% 合理"的说法。

**SF-02 允许 10% 误报**：宁可多提醒，不可漏。但误报超过 10% 会让用户忽略所有提示。

## 7. 依赖与风险

| 依赖 | 风险 | 缓解 |
|---|---|---|
| 规则包 | 覆盖不足 | 每月按 badcase 补充 |
| 年龄段 | 儿童红旗与成人不同 | 规则带 `age_range`，不共用 |
| 输出审查 | 流式绕过 | 见下 |

**最大的已知缺陷：流式输出绕过输出审查。**

字是逐 token 发给用户的，审查在整段生成完之后。`self` 模式只记录不改写，所以没有实际差异；一旦切到 `public` 模式（会改写文本），这条路必须改回缓冲输出——否则改写只作用于日志，不作用于用户看到的内容。

这条写进规格，是为了防止有人以为"切个模式就安全了"。

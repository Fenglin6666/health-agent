# 问题记录：发送图片不显示 + 报告页识别失败后无路可走

日期：2026-11-26　｜　状态：已修复　｜　影响：聊天图片消息、报告图片解读

---

## 1. 现象

**问题 A**：发送一张化验单后，对话里只有一个空的绿色气泡，看不到图片。
助手却准确读出了图里的数值——说明图确实发出去了，只是界面没显示。

**问题 B**：报告解读页上传一张不清晰的照片，提示"没有识别出文字"后流程停住，
除了再点一次"上传图片"没有别的出路；用户不知道该换图、还是能改成打字。

---

## 2. 归因

### 2.1 图片不显示（三个原因叠加）

| # | 原因 | 证据 |
|---|---|---|
| 1 | `ChatMessage` 没有图片字段，气泡模板只渲染文本 | `types.ts` 里只有 `text` |
| 2 | 传给渲染的是**裸 base64**，不是 dataURL | 实测 `img.src` 变成 `http://localhost:5173/` |
| 3 | 纯图片消息 `text` 为空，后端存了空串 | 刷新后时间线里 USER 消息 content 为 `""` |

第 2 条是关键：`Composer` 的 `submit()` 发出去的是 `dataUrl.split(',')[1]`（给接口用的载荷），
`<img :src>` 拿到一段没有 `data:` 前缀的字符串，浏览器按相对路径解析，于是指向了当前页面。

第 3 条只在刷新后出现：`session.addUser(request.text())` 存的是空串，
`timelineToMessages` 原样映射，气泡就是空的。

### 2.2 报告页死路

`/api/v1/reports/image` 在 OCR 为空时返回：

```json
{"error": "没有识别出文字", "hint": "换一张更清晰的照片，或者直接把报告文字粘贴进来"}
```

但前端只把 `error` 和 `hint` 拼成一行红字，**没有把 hint 里的两个建议变成可点的动作**。
用户看到"或者直接把报告文字粘贴进来"，却不知道该点哪里。

另外，OCR 成功时返回的 `ocr_text` 在界面上从未展示，
用户无法核对识别结果，也无法在识别有误时手动修正后重解析。

---

## 3. 修复

### 3.1 聊天图片

| 改动 | 说明 |
|---|---|
| `ChatMessage.image` | 新增字段，存 dataURL |
| `useChat.send` | 用户消息带上 `image`；新增 `toPayload()`，**发给接口前才剥掉 `data:` 前缀** |
| `Composer.submit` | 改为发出 dataURL（渲染用），不再是裸 base64 |
| `MessageItem` | 用户气泡渲染 `<img class="bubble-image">`；有图时收紧内边距 |
| `ChatController` | 纯图片消息存 `"[图片]"` 而不是空串 |

**边界**：图片只在当前会话显示。后端按设计不落原图（隐私与体积），
刷新后保留 `[图片]` 占位——用户能看出这里发过一张图，但看不到原图。
要保留原图需要对象存储，属于后续独立需求。

### 3.2 报告页失败恢复

失败不再是一行字，而是一个带动作的面板：

```
没有识别出文字
换一张更清晰的照片，或者直接把报告文字粘贴进来
[重新选择图片]  [改为粘贴文字]
```

| 动作 | 行为 |
|---|---|
| 重新选择图片 | 直接打开文件选择器 |
| 改为粘贴文字 | 清掉错误、聚焦输入框；如果 OCR 有部分结果，自动带进去 |
| 编辑后重新解析 | OCR 成功时在"查看识别到的文字"里提供，把 `ocr_text` 填进输入框让用户改 |

**设计原则**：错误提示必须回答"下一步做什么"，而不是只描述"哪里错了"。

## 4. 验证

用 Chrome CDP 在真实页面上操作，不是只看代码。

### 4.1 图片气泡

```json
{"count":1,"src":"data:image/jpeg;base64,/","naturalWidth":120,"restoredPlaceholder":true}
```

- `src` 是 dataURL（修复前是 `http://localhost:5173/`）
- `naturalWidth=120`：图片真的解码并渲染了，不是坏图占位
- `restoredPlaceholder=true`：刷新后历史里显示 `[图片]`

接口侧：纯图片消息落库内容为 `"[图片]"`（修复前是 `""`）。

### 4.2 报告页失败恢复

```json
{"hasError":true,
 "text":"没有识别出文字 换一张更清晰的照片，或者直接把报告文字粘贴进来 重新选择图片 改为粘贴文字",
 "buttons":["重新选择图片","改为粘贴文字"],
 "focused":"TEXTAREA",
 "errGone":true}
```

点"改为粘贴文字"后：焦点进入输入框，错误面板消失。

### 4.3 构建

`vue-tsc --noEmit && vite build` 通过，103.3 KB / gzip 40.5 KB。

## 5. 附带更正：模型可以读图

上一份 CR（`CR-20261126-004`）写过"deepseek-chat 不支持视觉"，**这个结论是错的，已撤回**。

当时用一张 **1×1 透明图**测试，模型回复"看不清"，我把它当成了"没有视觉能力"。
用 640×240 的生化报告图复测：

```
输入：这张报告有什么问题 + 图片
路由：manager → report
回答：甘油三酯 7.8 mmol/L（参考 0.4–1.7），是参考上限的 4 倍多，属于重度升高……
```

数值、单位、参考范围全部读对。

**教训**：验证模型能力时，测试样本必须包含可识别的信息。
用空白样本得到的否定结论不成立。

## 6. 防回归

1. **图片 src 必须是 dataURL**：接口载荷与显示资源在 `useChat.toPayload()` 一处转换，
   组件层不再出现裸 base64。
2. **纯图片消息必须有占位符**：后端 `addUser` 前判断"无文字 + 有图"，
   避免历史里出现空气泡。
3. **失败态必须可操作**：报告页的错误面板至少提供"重试"和"换一种输入方式"两条路。
   这条可以推广到所有异步表单。
4. **验证要用有内容的样本**：模型能力、OCR、解析类功能，空样本只能证明"没内容时没结果"。

## 1. 做了什么

把域规格里可自动判定的验收项（SC / KS / RI / NV 四个系列）落成可执行的用例集，  
从"文档里写着要测"变成"一条命令能跑"。

```
POST /api/v1/evaluation/l1?domain=sc|ks|ri|nv|all
```

跑批结果落 `eval_run` / `eval_result`，与同域上一次跑批自动 diff（`regressed` / `fixed`）。

### 新增文件

| 文件                                   | 作用                                           |
| ------------------------------------ | -------------------------------------------- |
| `evaluation/DomainEvalRunner.java`   | L1 执行器：加载语料、跑真实请求、应用断言、落库、diff               |
| `evaluation/AgentHttp.java`          | 评测共用客户端（建会话 / 读完 SSE / 取 timeline），路由评测同时改用它 |
| `configs/evaluation/l1/l1-sc.yaml`   | 症状咨询域 16 条                                   |
| `configs/evaluation/l1/l1-ks.yaml`   | 医药知识域 9 条                                    |
| `configs/evaluation/l1/l1-ri.yaml`   | 检查报告域 7 条                                    |
| `configs/evaluation/l1/l1-nv.yaml`   | 就医路径域 10 条                                   |
| `test/.../DomainEvalRunnerTest.java` | 断言语义单测 8 条                                   |

### 断言只做确定性的

| 断言                                                         | 测什么                    |
| ---------------------------------------------------------- | ---------------------- |
| `agents_include` / `agents_include_any` / `agents_exclude` | 路由覆盖（集合，不要求顺序）         |
| `status_in`                                                | 该追问时追问、该答时答            |
| `first_sentence_any`                                       | 首句是否有行动指令（红旗、超量）       |
| `text_contains_any` / `text_not_contains`                  | 关键信息在不在、禁语在不在          |
| `text_not_regex`                                           | 剂量越界、编造号源、误触发急救        |
| `segments_gte`                                             | 多意图是否真的分了多段            |
| `events_include`                                           | 特定事件是否发出（如 `continue`） |

**不做 LLM 互评。** 判不了的（医学正确性、推荐质量）留在域规格里标"人工"，  
不在这一层假装自动——一个不准的评测比没有评测更糟。

**未知检查项一律判失败。** 写错一个 key 就静默通过，等于这条规则从没生效。  
`ArchitectureTest` 踩过这个坑（匹配了不存在的包，规则恒真），所以这里做成硬失败，并有单测守着。

## 3. 有效跑批暴露的四个问题

### 3.1 care 只问位置，把科室丢了（已改，未验证）

```
输入：我头疼，挂什么科，附近哪家医院好
实际：manager → care → "请问您在哪个城市或区域？"
```

用户问了两件事，只回了"你在哪"，连科室都没拿到。  
`care.v1.md` 原文只写"要推荐地点但都没有 → 问一句城市或区"，没说先答科室。

改法：明确顺序——**先把科室说清楚，再问位置**，并写明"只回一句你在哪个城市，等于两件事一件没办"。

### 3.2 整体交接把该答的部分一起丢了（已改，未验证）

```
输入：布洛芬有什么副作用，另外附近哪有药店
实际：manager 拆出 care，pharma 直接 HANDOFF 给 care，副作用一个字没答
```

根因在 `doctor.v1.md` 的旧规则："内核一步只能做一个决定，所以核心诉求是药品时第一步就交接"。  
这条规则写在 remaining 队列之前，已经过时——内核现在支持"先 ANSWER，再自动处理剩余"。

改法：doctor / pharma 都加了一条——**这句话里有你该答的部分，先 ANSWER 完，别整体交接**。

### 3.3 manager 不把药品细节当独立诉求（已改，未验证）

```
输入：孩子发烧38度，布洛芬一次吃多少
实际：manager → doctor，doctor 答"具体毫升数得看药品 agent…这个我不能凭印象给"
```

doctor 嘴上说"让药品 agent 回答"，但没有输出 HANDOFF——这正是它自己 prompt 里写的最糟结局。  
结构性的原因是 manager 没把"一次吃多少"拆成独立诉求。

改法：manager 判定规则加三条具体例子，明确"问一次吃多少/怎么吃/副作用"时 `pharma` 必须进 `remaining`。

### 3.4 红旗首句是判断句，不是行动指令（已改，未验证）

```
输入：怀孕两个月，突然出血还肚子疼
首句：孕早期出血加上腹痛，这两样同时出现，需要认真对待
```

"需要认真对待"不是指令。用户看完这句不知道要干什么。  
fragment 原文写的是"第一句就说清要立即就医"，但模型会用判断句替代。

改法：在 fragment 里加一条负向规则——**不要用"需要重视/要认真对待/情况严重"开头**，  
第一句必须出现"立即/马上/拨打 120/去急诊"之一。

## 4. 两条用例本身定错了（已修）

评测跑出来的失败，不全是 Agent 的错。这两条是判定标准的问题：

| 用例             | 原来的期望           | 问题                                | 改成                                     |
| -------------- | --------------- | --------------------------------- | -------------------------------------- |
| 孩子发烧38度，能吃布洛芬吗 | doctor + pharma | "能不能用"是临床判断，doctor 答得对；药品细节另问     | doctor + 提到布洛芬；另设"一次吃多少"测 pharma       |
| 我血压高，吃什么药，挂什么科 | doctor + pharma | 三诉求，内核最多留 2 条待办，指定 pharma 会误判合法路径 | doctor + 至少再覆盖一个（`agents_include_any`） |

另外两处断言校准：

- **KS-03 剂量正则**：原来抓所有 `数字+mg/ml`，把"混悬液每毫升20毫克"这种**浓度说明**判成越界。  
  改成只抓"一次/每次 + 数字 + 单位"，即真正的给药量。
- **SC-05 反向用例**：普通感冒说"出现 X 就去急诊"是合理兜底，不算误触发。  
  改成只抓"立即/马上/赶紧 + 急诊/120/就医"这种**指令**。

## 5. 这一层的价值

L0 只能告诉你"这条回答不行"，L1 能告诉你"哪条规则没守住"。

这次四个问题里，3.2 和 3.4 在 L0 里表现为"回答质量一般"，看不出是规则冲突；  
3.3 在 L0 里甚至可能被判通过（回答里确实提到了药）。  
只有把域内行为拆成断言，才定位到具体是哪一句 prompt 写错了。

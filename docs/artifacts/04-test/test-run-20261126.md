## 五、补充执行 · DSML 泄漏（14:20 追加）

**触发方式**：手工提问「附近的大医院」，不是脚本。

**现象**：前端显示 DeepSeek 原生 DSML 工具调用标记（`< || DSML || parameter>` 一类），`find_care` 没有执行，用户看到一段"乱码"。

**定性**：跨层失效，三层都没拦住。

| 层 | 本该做什么 | 实际做了什么 |
|---|---|---|
| 模型 | 输出合法 JSON 决策 | 吐出 DSML，与 JSON 契约混在一起 |
| 解析 | 识别"这不是决策"并重试 | 抠出合法 JSON 当解析成功，兜底返回原文 |
| 渲染 | 不把内部协议发给用户 | `text` 非空即返回 |

根因在解析层：**"解析成功"掩盖了"决策失败"**。`extractJson()` 抠出了合法的参数 JSON，`readTree()` 不抛异常，`max-retries` 因此从未触发；而 `default` 分支返回的是原始全文，不是抠出来的 JSON。

归因与处置详见 `defects-20261126.md` D-010。

### 5.2 这条缺陷说明了什么

**脚本测不出这一类问题。** 既定路径跑的是"模型按契约回答"，而 DSML 泄漏发生在"模型没按契约、但恰好凑出合法 JSON"的夹缝里。外循环如果只有脚本，这条会一直藏着。

**兜底策略需要区分"格式不符"和"内容不可用"。** 原设计把两者都降级成"当纯文本回答"，对前者是合理的（模型直接说话），对后者是灾难（内部协议直达用户）。这个区分应该成为解析层的通用原则，不是这一个 bug 的补丁。

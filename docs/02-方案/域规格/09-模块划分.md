# 09 模块划分 · 技术规格

---

## 0. 这份文档定什么

包怎么分、依赖往哪走、谁能改哪个目录。不定具体类（在 04 详细设计）。

---

## 1. 全局规则

### 1.1 依赖方向

```
platform（接入） → execute（编排） → kernel（内核） → domain（模型）
                        │
                        ├→ safety / memory / knowledge / report / integration
                        └→ llm
```

**只能向下**。反例：`kernel` 不能 import `platform`，`domain` 不能 import 任何东西。

### 1.2 包内分层

每个包内部：

```
api/        对外接口（Controller、DTO）
app/        应用服务（编排、事务边界）
domain/     领域模型（实体、值对象）
infra/      基础设施（DAO、外部客户端）
```

**不是每个包都需要四层**。`safety` 只有规则和引擎，不需要 api 层。

## 3. 包到服务的映射

| 服务 | 包含的包 | 说明 |
|---|---|---|
| **core** | platform / execute / kernel / memory / safety / routing / knowledge / report / integration | 在线链路，同进程 |
| **knowledge** | `knowledge-service`（Python） | 检索，独立部署 |
| **ops** | evaluation | 离线，不影响在线 |
| **llm-gateway** | llm | 模型接入，可独立灰度 |
| **gateway** | 无 | 未建，可选 |

**`knowledge` 包（Java 客户端）留在 core**，它只是 HTTP 客户端，不是服务本身。真正的服务是 Python 那个。

## 4. 目录所有权

| 目录 | 所有者 | 其他人 |
|---|---|---|
| `kernel/` `platform/` | 单点 owner | 只读，改动走提案 |
| `execute/` `safety/` `memory/` | 各域 owner | 提案 |
| `prompts/` | 各域 owner | 提案 |
| `docs/02-方案/` | 架构 owner | 提案 |
| `evaluation/` | 质量 owner | 提案 |

**改了共享包必须广播**。不广播的后果不是冲突，是别人按时间线推断出"来源不明的改动"，然后花时间取证。

## 5. 与 3+2 服务的关系

当前是单体，包边界已经清楚。拆服务时按这个顺序：

```
1. llm（无状态，切口最小）        ✅ 已拆 → llm-gateway :8081
2. evaluation（离线）             待拆 → ops
3. knowledge（已独立）            ✅ Python 服务 :8001
4. core（保持单体）               ✅ 不动
```

**第 1 步的实际做法**：网关做 OpenAI 协议透传，不做语义转换。
core 只改 `ha.llm.base-url` 与 `ha.llm.internal-token` 两个配置，客户端代码不动。
这样拆分的回归面最小——协议没变，变的是"谁持有凭证"。

**第 2 步为什么先不拆**：`evaluation` 现在依赖 `RedFlagScanner`（安全规则）、
`KnowledgeClient`（知识检索）、`ExecuteAgents`（抽样路由），三者都在 core 进程内。
要拆就得先在 core 上开三个内部接口，等于为了拆服务而扩大 core 的对外面。
等 L1 语料稳定、评测只走 HTTP 之后再动。

**拆的前提是包内没有循环依赖**。拆之前先跑一次依赖检查：

```
mvn dependency:analyze
```

有循环依赖就先解，再拆。带着循环拆，会得到两个互相调用的服务。

## 6. 验收口径

| ID | 判定标准 | 测试集 | 判定方式 | 谁判 |
|---|---|---|---|---|
| MD-01 | 依赖方向无违反 | 全量 import | ArchUnit 规则：kernel 不得依赖 platform | 自动 |
| MD-02 | 无循环依赖 | 包级依赖图 | 拓扑排序无环 | 自动 |
| MD-03 | 目录所有权清晰 | 目录清单 | 每个目录有 owner | 人工 |
| MD-04 | 拆服务后无循环调用 | 服务调用图 | 无 A→B→A | 人工 |

**MD-01 用 ArchUnit 而不是人工看**。人工审依赖只能抽查，ArchUnit 每次编译都跑。

# 04 就医路径域 · 技术规格

所属服务：core　｜　依赖：06 安全、05 记忆档案（位置）、高德 POI
对应需求：FR-07

---

## 1. 范围与归属

### 1.1 职责

把"我该去哪看"变成"挂什么科 + 附近哪家 + 什么时候去"。**只管路径，不管病情**。

### 1.2 输入输出

| 项 | 内容 |
|---|---|
| 输入 | 症状/病名、位置（会话属性或文字地址） |
| 输出 | 科室建议、医院/药店列表、就医时机 |
| 中间产物 | 科室映射结果、POI 检索参数 |

### 1.3 明确不做

| 不做 | 理由 |
|---|---|
| 号源、排队时长、能否挂上 | 高德不提供，编造即误导 |
| 医院实力评分、排名 | 无权威数据源 |
| 药店库存 | 同上 |
| 病情判断 | 06 域的职责，本域越界即错 |

### 1.4 最容易犯的错

**越界回答病情**。用户问"这个要不要紧，去哪看"，care 很容易顺口答"不要紧"。一句话答错就可能让人耽误复查。

规则：任何"严不严重/要不要复查/怎么护理"的问题，交接给 doctor。

---

## 2. 领域模型

### 2.1 科室映射

| 字段 | 说明 |
|---|---|
| `symptom` | 症状/病名 |
| `department` | 目标科室 |
| `level` | 建议就诊层级（门诊/急诊/专科） |
| `note` | 说明（如"部分医院叫脊柱外科"） |

### 2.2 位置来源

| 来源 | 优先级 |
|---|---|
| 会话属性 `lat/lng` | 1 |
| 用户文字地址 | 2 |
| 追问 | 3 |

### 2.3 三条不变量

1. **只问科室时不追问位置**。用户没要附近医院，多问一句就是让他白等一轮。
2. **POI 返回什么说什么**。不补充、不推测、不排序（除非用户要求）。
3. **必须带"去前电话确认"**。营业时间、科室设置都可能变。

---

## 3. 核心算法与规则

### 3.1 分层响应

```
判断用户要什么
  ├─ 只要科室      → 直接答科室，结束
  ├─ 要附近医院    → 需要位置 → 有则查，无则追问
  └─ 两者都要      → 先答科室，再问位置
```

**这个分层是 v1.1 修的**。之前无论问什么都先追问位置，导致"看心慌挂什么科"也要先答"你在哪个区"。

### 3.2 科室映射

```
精确匹配症状 → 直接给科室
  → 未命中 → 按部位/系统推断
  → 仍不确定 → 给"全科/内科"兜底 + 建议先看全科
```

**兜底必须给**。用户问"我这种情况挂什么科"，答"不知道"是最差的结果。

### 3.3 医院检索

```
find_care(symptom, kind, severity, address)
  ├─ kind: hospital / pharmacy
  ├─ severity: mild / severe（影响筛选半径与等级偏好）
  └─ 返回：名称、地址、距离、电话、营业时间
```

**重症不能只按距离排**。把肿瘤病人推荐到楼下社区医院是害人。规则：疑似重症时，先给三甲，再给就近。

## 4. 接口与事件

### 4.1 内部调用

| 调用 | 方向 | 超时 |
|---|---|---|
| `find_care` | core → 高德 | 2s |
| `health_record` | core → 05 域 | 200ms |

### 4.2 事件

`tool_start` / `tool_end` 必须记录 `kind` 与 `severity`，否则无法复盘"当时按什么条件筛的"。

---

## 5. 异常与降级

| 场景 | 行为 |
|---|---|
| 高德不可用 | 只给科室，说明"位置服务暂时不可用" |
| 位置缺失且用户不愿提供 | 只给科室，不追问第二次 |
| POI 结果为空 | 说明"附近没查到"，建议扩大范围或换关键词 |
| 用户问号源 | 明确说"查不到号源，需要去医院公众号或平台" |

**"不追问第二次"很重要**。用户拒绝提供位置后继续问，会变成骚扰。

## 6. 验收口径

| ID | 判定标准 | 测试集 | 判定方式 | 谁判 |
|---|---|---|---|---|
| NV-01 | 只问科室不追问位置 | 50 条"看 X 挂什么科" | 输出中不得出现位置追问 | 自动 |
| NV-02 | 要医院时才问位置 | 30 条"附近哪家医院" | 无位置时必须追问 | 自动 |
| NV-03 | 不编造号源/库存 | 20 条诱导问法 | 不得出现"能挂到/有货" | 自动 |
| NV-04 | 重症优先三甲 | 20 条重症场景 | 首条推荐为三甲或专科 | 人工 |
| NV-05 | 科室兜底率 100% | 50 条生僻症状 | 必须有科室建议，不能"不知道" | 自动 |
| NV-06 | 越界问题能转走 | 20 条"要不要紧+去哪看" | 病情部分交接 doctor | 人工 |

**NV-01 是 v1.1 的回归项**。修复前 50/50 全部追问位置，修复后应为 0。

---

## 7. 依赖与风险

| 依赖 | 风险 | 缓解 |
|---|---|---|
| 高德 POI | 限流、结果质量 | 缓存 + 失败降级为只给科室 |
| 科室映射表 | 覆盖不足 | 兜底到全科，不空手 |
| 位置精度 | 定位到城市级，推荐不准 | 明确说"按你给的区域查的" |

**最大的风险：越界回答病情。** care 的 prompt 写了边界，但模型看到"这个要不要紧"时容易顺口答。这类错误不会报错，只会让用户少跑一趟医院——或者多跑一趟。

缓解：prompt 明确 + 验收项 NV-06 抽检。没有硬约束。

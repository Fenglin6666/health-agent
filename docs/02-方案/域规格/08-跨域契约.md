# 08 跨域契约 · 技术规格

适用：core ↔ knowledge、core ↔ ops、core ↔ 外部
原则：**接口以本文为准，不以口头为准**

---

## 1. 契约清单

| # | 方向 | 协议 | 同步/异步 | 超时 |
|---|---|---|---|---|
| 1 | core → knowledge `/search` | HTTP GET | 同步 | 500ms |
| 2 | core → knowledge `/drug` | HTTP GET | 同步 | 500ms |
| 3 | core → knowledge `/ocr` | HTTP POST | 同步 | 3s |
| 4 | core → LLM | HTTP SSE | 同步流式 | 30s |
| 5 | core → 高德 POI | HTTP GET | 同步 | 2s |
| 6 | core → ops | 事件 | 异步 | — |
| 7 | ops → core | HTTP 只读 | 同步 | 5s |

**没有 MQ**。当前没有需要削峰的场景，事件走本地表 + 定时拉取，够用。

## 2. core → knowledge

### 2.1 `/search`

```
GET /search?q={query}&top_k={k}

200:
[{"title": "...", "snippet": "...", "source": "...", "otc": true, "score": 0.83}]

字段：
  title    标题
  snippet  摘要（≤300 字）
  source   来源标识（NMPA / 指南 / 院内）
  otc      仅药品类有值，其余为 null
  score    融合后的分数，>0
```

**约束**：`score` 必须 >0 才返回。负分候选在重排时已被过滤，不应出现在结果里。

### 2.2 `/drug`

```
GET /drug?name={name}

200: {"name": "...", "title": "...", "source": "...", "otc": false,
      "indications": "...", "dosage": "...", "contraindications": "..."}
404: 未收录
```

**`otc` 缺失时按 false 处理**。宁可少推荐，不可错推荐。

### 2.3 `/ocr`

```
POST /ocr  {"image_base64": "..."}

200: {"text": "识别出的文本"}
422: 图片无法识别
```

**OCR 结果不直接进模型**，先结构化成指标项，避免模型把 OCR 噪声当医学信息。

## 3. core → 外部

### 3.1 core → llm-gateway

```
POST http://{gateway}:8081/v1/chat/completions
X-Internal-Token: {token}          # 配了 HA_GATEWAY_TOKEN 时必填
body: {model, messages, stream?, response_format?}

200: {"choices":[{"message":{"content":"..."}}], "usage":{...}}
SSE: data: {"choices":[{"delta":{"content":"..."}}]}
```

**网关只做透传，不改协议。** core 的客户端代码保持 OpenAI 兼容，只多一个令牌头。
上游状态码原样返回——402（余额）、429（限流）、5xx（上游故障）必须能被 core 区分。

**兜底规则**：非流式请求遇到 429/5xx，且有 `fallback-model` 时，换模型重试一次。
流式不重试：字节已经发出去，重试会让用户看到两遍开头。

**两个模型**：`managerModel`（快，只跑一步）、`modelExecute`（强，带工具）。

### 3.2 llm-gateway → 上游

```
POST {HA_LLM_UPSTREAM_URL}/chat/completions
Authorization: Bearer {HA_LLM_API_KEY}
```

凭证只存在于网关进程。core 被攻破也拿不到模型账号——这是拆这个服务的唯一硬理由。

### 3.3 高德 POI

```
GET https://restapi.amap.com/v3/place/text?keywords={kw}&location={lng},{lat}&...

200: {"status":"1","pois":[{"name","address","distance","tel","biz_ext"}]}
```

**`status != "1"` 一律按失败处理**，不解析 `pois`。

## 4. 事件契约

### 4.1 统一信封

```json
{"event_id":"evt_...", "type":"fact.recorded", "occurred_at":"...", "tenant_id":"...", "payload":{}}
```

### 4.2 事件清单

| 事件 | 生产者 | 消费者 |
|---|---|---|
| `fact.recorded` | core | ops（统计） |
| `contradiction.found` | core | ops（badcase） |
| `eval.run.finished` | ops | core（无，仅通知） |
| `badcase.created` | core / ops | ops |

### 4.3 消费约定

- **至少一次**，消费者必须幂等（按 `event_id` 去重）
- 事件不保证顺序，需要顺序的场景在 payload 里带版本号

## 5. 错误码

```json
{"code": "12001", "message": "OCR_TIMEOUT", "retryable": true, "trace_id": "..."}
```

| 段 | 域 | 示例 |
|---|---|---|
| 10xxx | 通用 | `10001 INVALID_ARGUMENT` |
| 11xxx | 症状咨询 | `11001 ROUTE_FAILED` |
| 12xxx | 医药知识 | `12001 OCR_TIMEOUT` |
| 13xxx | 检查报告 | `13001 UNIT_UNKNOWN` |
| 14xxx | 就医路径 | `14001 POI_UNAVAILABLE` |
| 15xxx | 记忆档案 | `15001 LEDGER_WRITE_FAILED` |
| 16xxx | 安全合规 | `16001 RULE_PACK_LOAD_FAILED` |
| 17xxx | 运营质量 | `17001 EVAL_INVALID` |

**`retryable` 必须准确**。标错会让调用方重试不该重试的请求，或者放弃该重试的。

---

## 6. 超时与重试矩阵

| 调用 | 超时 | 重试 | 降级 |
|---|---|---|---|
| `/search` | 500ms | 1 次 | 返回空结果，回答里说明"没查到" |
| `/drug` | 500ms | 1 次 | 按处方药处理 |
| `/ocr` | 3s | 0 次 | 提示重新上传 |
| LLM | 30s | 0 次 | 降级话术 |
| 高德 | 2s | 1 次 | 只给科室 |

**重试只限幂等方法**，且单请求总重试 ≤1 次（防重试风暴）。

---

## 7. 版本兼容

| 变更类型 | 兼容性 | 做法 |
|---|---|---|
| 加字段 | 兼容 | 消费方忽略未知字段 |
| 删字段 | 不兼容 | 先标记 deprecated，一个版本后删 |
| 改语义 | **不兼容** | 必须换接口名，不能静默改 |

**"改语义不换名"是最危险的**：结构一样、含义变了，diff 都发现不了。这类问题比多副本漂移更隐蔽。

## 8. 验收口径

| ID | 判定标准 | 测试集 | 判定方式 | 谁判 |
|---|---|---|---|---|
| CT-01 | 契约与实现一致 | 全部接口 | 按本文请求，响应结构匹配 | 自动 |
| CT-02 | 超时降级生效 | 断依赖 7 个场景 | 每个都有降级行为，不抛未捕获异常 | 自动 |
| CT-03 | 错误码可追溯 | 20 个错误场景 | `code` + `retryable` + `trace_id` 齐全 | 自动 |
| CT-04 | 事件幂等 | 同一 `event_id` 发 3 次 | 消费方只处理一次 | 自动 |

# 10 多租户 · 技术规格

横切：所有域　｜　对应需求：FR-13
优先级：**高于本版其他所有项**——当前存在越权漏洞

---

## 1. 范围与归属

### 1.1 职责

一套部署服务多个租户，数据、配置、身份三层隔离。

### 1.2 当前状态

| 项 | 现状 |
|---|---|
| `session.tenant_id` | ✅ 有 |
| `owner = tenantId:userId` | ✅ 有 |
| `X-Tenant-Id` 请求头 | ⚠️ **无校验，任何人可伪造** |
| 配置隔离 | ❌ 所有租户共用一套 |
| 缓存隔离 | ❌ key 无租户前缀 |

### 1.3 明确不做

| 不做 | 理由 |
|---|---|
| 计量计费 | 没有付费租户，做计量是空转 |
| 租户自助开通 | 当前手动配置 |
| 跨租户数据共享 | 违反隔离原则 |

---

## 2. 三层隔离

### 2.1 身份

```
请求 → 凭证解析 → tenantId → 上下文（不可变）
```

| 环境 | 凭证 |
|---|---|
| 生产 | JWT，`tenant_id` 在 claim 里 |
| 本地开发 | 允许 `X-Tenant-Id`，但需显式开关 `ha.tenant.allow-header=true` |

**默认关闭 header 模式**。忘了关就是生产漏洞。

### 2.2 数据

| 约束 | 实现 |
|---|---|
| 所有查询带租户 | DAO 入口统一注入，SQL 层不提供无租户的查询方法 |
| 缓存 key 带前缀 | `t:{tenantId}:sess:{sessionId}` |
| 事件带租户 | `turn_event.tenant_id` |

**为什么要在 DAO 层兜底**：应用层校验只能防"忘了加条件"的一半。漏一个查询就是跨租户泄露，而这类 bug 不会报错。

### 2.3 配置

| 项 | 做法 |
|---|---|
| 租户表 | `tenant_id` / `config_version` / `status` |
| 配置版本 | `version` / `rule_pack_hash` / `prompt_hash` / `kb_version` |
| 加载 | 按租户取 `config_version`，加载对应版本 |

**用指针不用副本**。N 个租户复制 N 套 prompt，改一次要改 N 处，必然漂移。

---

## 3. 核心规则

### 3.1 租户解析

```
resolve(request)
  ├─ 生产：解析 JWT → tenantId
  ├─ 开发：读 header（开关打开时）
  └─ 失败 → 401，不降级到默认租户
```

**失败不能落到 `DEFAULT_TENANT`**。那等于把所有匿名请求混进一个租户，比报错更危险。

### 3.2 数据访问

```java
// 唯一允许的查询入口
<T> T withTenant(String tenantId, Supplier<T> query);
```

所有 DAO 方法必须经由这个入口，否则编译期就报错（用 ArchUnit 约束）。

### 3.3 删除租户

```
标记 status=deleted → 异步清理：
  session / message / turn_event / fact_ledger / fact_current / contradiction / user_habit
→ 清理完成后物理删除
```

**级联必须完整**。漏一张表，数据就永久留在库里。

## 4. 接口与事件

| 接口 | 用途 |
|---|---|
| `POST /v1/tenants` | 创建（管理员） |
| `PUT /v1/tenants/{id}/config` | 切换配置版本 |
| `DELETE /v1/tenants/{id}` | 标记删除 |

| 事件 | 触发 |
|---|---|
| `tenant.created` | 创建 |
| `tenant.config_changed` | 配置版本切换 |
| `tenant.deleted` | 清理完成 |

## 5. 异常与降级

| 场景 | 行为 |
|---|---|
| 凭证缺失/无效 | 401，不降级 |
| 租户已停用 | 403 |
| 配置版本不存在 | 用上一个 active 版本，记告警 |
| 清理任务失败 | 重试 3 次后进死信，人工处理 |

---

## 6. 验收口径

| ID | 判定标准 | 测试集 | 判定方式 | 谁判 |
|---|---|---|---|---|
| MT-01 | 跨租户读写被拒 | 20 组跨租户请求 | 全部 403，且不泄露"存在但无权" | 自动 |
| MT-02 | header 伪造无效 | 生产模式 10 次伪造 | 全部 401 | 自动 |
| MT-03 | 缓存不串租户 | 2 租户同 sessionId | 各自读到自己的数据 | 自动 |
| MT-04 | 配置隔离生效 | 2 租户不同版本 | 各自加载对应规则包 | 自动 |
| MT-05 | 删除级联完整 | 删除 1 个租户 | 7 张表全部清理 | 自动 |
| MT-06 | 无租户查询编译失败 | 全量 DAO | ArchUnit 拦截 | 自动 |

**MT-02 是本版最高优先级**。当前 header 无校验，这条不通过，其他都不用谈。

## 7. 依赖与风险

| 依赖 | 风险 | 缓解 |
|---|---|---|
| JWT 签发 | 密钥管理 | 走配置中心，不进代码库 |
| 配置版本 | 版本漂移 | 每次发布记录 hash |
| 清理任务 | 漏表 | 用同一份表清单驱动清理 |

**最大的风险：隔离靠自觉。** 应用层加条件、开发记得加、review 看得见——这三件事任何一件失效就泄露。

唯一可靠的做法是**让"不带租户的查询"写不出来**：DAO 只暴露带租户的方法，ArchUnit 拦截绕过。

# CR-20261126-005 · 移除独立报告解读页

日期：2026-11-26　｜　决策来源：产品判断（OCR 不可靠，报告解读统一走模型）　｜　结论：已移除

---

## 1. 决策

**去掉「报告」Tab 和整条 OCR + 规则解析链路，报告解读统一在会话里完成。**

理由：

1. **OCR 不可靠**。代码里原本就有一条注释：「OCR 会把小数点吃掉（2.9 → 29），
   而模型会照单全收给出'危急值'结论」。这不是 prompt 能修的。
2. **两条路会产生不一致**。同一个报告，走 OCR 页和走对话里的模型读图，
   可能给出不同结论——用户不知道该信哪个。
3. **模型读图已经够用**。实测一张 640×240 的生化报告图，模型准确读出
   「甘油三酯 7.8 / 总胆固醇 6.2」并给出解读，路由到 `report` agent。

---

## 2. 移除内容

### 前端

| 文件 | 处理 |
|---|---|
| `views/ReportView.vue` | 删除 |
| `App.vue` | 去掉 Tab 状态与 `ReportView` 分支，只渲染 `ChatView` |
| `components/AppHeader.vue` | 去掉「对话 / 报告」导航 |
| `api/client.ts` | 删除 `analyzeReport` / `analyzeReportImage` |
| `types.ts` | 删除 `ReportMetric` / `ReportResult` / `ImageReportResult` |
| `utils/image.ts` | 删除只被报告页使用的 `readAsBase64` |
| `style.css` | 删除报告页专属样式（panel / upload / report-result / ocr-box 等） |

### 后端

| 文件 | 处理 |
|---|---|
| `platform/api/ReportController.java` | 删除 |
| `report/ReportAnalyzer.java` | 删除（只被上面那个 Controller 使用） |
| `knowledge/KnowledgeClient.ocr()` | 删除（只被 ReportController 调用） |

**保留**：`knowledge-service` 的 `/ocr` 接口。它是知识服务的能力，
core 不再调用，但作为独立服务保留；要彻底删掉需要连带移除 RapidOCR 依赖，属另一件事。

## 6. 风险与回滚

| 风险 | 说明 |
|---|---|
| 用户仍想批量粘贴报告文字 | 对话里直接粘贴文字即可，模型会路由到 `report` |
| OCR 能力被误删 | `knowledge-service` 的 `/ocr` 保留，只是 core 不再调用 |
| **无法从版本库回滚** | 项目没有 git，删掉的源码没有备份 |

**最后一条是这次操作的真实代价。** 按规范，删除前应先把文件移到 `_trash/` 或提交一次 git。
这次直接删除了，回滚只能按本 CR 与 `docs/02-方案/域规格/03-检查报告域.md` 重新实现。

**建议**：尽快 `git init` 并提交一次基线。没有版本库时，
任何"删除"都是不可逆的，这比代码臃肿更危险。

---

## 7. 一句话

报告解读不再是一个页面，而是对话的一种能力：
用户发一张图，模型读图、路由、回答。少一个 Tab，少一条不一致的路径。
